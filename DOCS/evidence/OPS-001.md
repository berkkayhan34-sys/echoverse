## Scope

- Added a server-owned structured JSON logger with stable event IDs and
  validated opaque correlation identifiers.
- Added process-local request, socket, rejection, and timing metrics with a
  bounded metric cardinality and a non-sensitive `/health` snapshot.
- Replaced server runtime `console` diagnostics with structured records.
- Added redaction tests for credentials, authorization, private content,
  personal data, identity identifiers, malformed correlation values, and
  bounded metrics.
- Documented production diagnostics, host retention, access control, incident
  lookup, and evidence-sharing rules in `DOCS/operations.md`.

## Privacy and security invariants

- Passwords, access/refresh tokens, cookies, authorization headers, OAuth
  codes, message bodies, attachment/media data, and user/account/session/socket
  identifiers are never serialized as log values.
- Request query strings, request bodies, and URL paths are not emitted by the
  request completion logger.
- Correlation identifiers are restricted to safe characters and replaced with
  random opaque identifiers when malformed or oversized.
- Metrics accept only bounded names and values, retain no request data, and
  reset with the process. The public health snapshot contains only counters and
  timing aggregates.

## Operational limitations

The application emits safe records to standard output and does not claim that
external host retention, encryption, access roles, or public-release
activation are configured. Those controls remain owner-operated and are
documented in `DOCS/operations.md` and `DOCS/governance.md`; restricted host
logs must not be committed to this repository.
