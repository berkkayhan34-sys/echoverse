## Blocker

The implementation cannot be completed honestly without external release-owner
inputs. The repository has no configured GitHub Actions signing secrets or
variables, and the release workflows currently set
`CSC_IDENTITY_AUTO_DISCOVERY=false` for all desktop targets. Local macOS
`codesign`, `xcrun`, and `notarytool` executables are present, but no Apple
Developer signing identity, team/notarization credentials, Windows publisher
certificate, or selected signing provider is available in the authorized
workspace or repository configuration.

These values cannot be invented, generated safely inside the repository, or
replaced with a local unsigned build. Unsigned artifacts remain validation-only
and must not be called production-ready.

## Safe inspection performed

- Inspected `DOCS/release.md`, ADR-0006, the unresolved-decision register, the
  roadmap, and all desktop release workflows.
- Confirmed the current release workflow builds and validates unsigned Windows,
  macOS Intel, and macOS Apple Silicon artifacts only.
- Listed repository GitHub Actions secret and variable names without reading any
  secret values; none were configured for signing.
- Confirmed the local host has macOS signing command-line tools, which does not
  provide the required identities or CI credentials.

## Required owner decision

Choose and provision one supported signing arrangement for both platforms:

1. Apple Developer ID Application certificate plus App Store Connect API key or
   approved notarytool credential, and a Windows Authenticode publisher
   certificate with its protected CI storage/provider; or
2. an owner-selected managed signing provider that supplies both platform
   identities and a documented verification/key-rotation interface.

After that decision, the repository work is to wire fail-closed CI signing,
verify publisher identity and updater assets, generate checksums/provenance,
and document rotation and forward-recovery/rollback evidence.
